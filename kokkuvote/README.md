# Kursuse kokkuvõte ja refleksioon

Git on kaasaegne hajutatud versioonihaldussüsteem, mida kasutatakse failide ja koodi muudatuste jälgimiseks. Seda rakendavad IT-meeskonnad üle maailma, et teha tõhusalt koostööd, vältida andmete kadumist ja hoida arendusprotsessi ajalugu selgena. Peamine erinevus käskude "commit" ja "push" vahel seisneb nende mõjualas. Commit salvestab tehtud muudatused lokaalselt kasutaja arvutis, luues projektist kindla hetketõmmise. Push seevastu saadab kõik lokaalselt salvestatud commitid üles serverisse, näiteks GitHubi keskkonda, muutes need kättesaadavaks ka teistele tiimiliikmetele. 

Harude (branches) kasutamine on äärmiselt kasulik, sest see võimaldab arendada uusi funktsioone või parandada vigu isoleeritud keskkonnas ilma peamist koodibaasi rikkumata. Pull Request on meeskonnatöö nepääsmatu osa, mida on vaja koodi kontrollimiseks ja ülevaatamiseks enne selle ühendamist peaharuga. See võimaldab kolleegidel teha koodikontrolli (code-review), arutada muudatusi ja minimeerida vigade teket lõpptootes. 

Git erineb oluliselt failide tavalisest kopeerimisest USB-mälupulgale, kuna see suudab erinevate inimeste tehtud muudatused automaatselt kokku sulatada ja säilitab täpse ajaloo selle kohta, kes ja millal mingeid korrektsioone tegi. GitHubi tööriistad on otseselt seotud projektijuhtimisega, kus Issues sektsioon asendab ülesannete nimekirja ning Projects vahekaart võimaldab luua Kanbani tahvleid töö progresses jälgimiseks. Kavatsen kindlasti GitHubi ka edaspidi kasutada oma koolitööde, laborite ja isiklike projektide hoiustamiseks, et luua tulevastele tööandjatele professionaalne portfoolio. Selle praktilise töö juures oli minu jaoks kõige lihtsam kaustade struktuuri loomine veebiliideses, ning kõige keerulisemaks osutus harude haldamine ja veendumine, et koodi ühendamisel ei tekiks konflikte.
